# Vocabularium 0.16.5

## Upgrade

Upgrading from 0.16.4 to 0.16.5 keeps every account, deck, page, card and clip. Stop the API, back up with `npm run db:backup -- .data/backup-before-0.16.5.dump` (a file it has not written before), run `npm run db:migrate` (migration `0019` renames the module type `english-british` and `english-american` to `english` in deck modules, components and attempts, [D34](../decisions/d34.md)), start the API with 0.16.5, then replace the extension's files and reload it: a 0.16.4 extension doesn't know the `english` module. What a user sees change: the module window lists one `English` in place of `English (British)` and `English (American)`; a deck or page that had either now has `English`, its cards as they were; a new or retried English card writes whatever proper English the model gives, British or American, and speaks an English key as selected. English Pronunciation speaks in the voice named for `english.pronunciation` in `ELEVENLABS_VOICES`, otherwise in `en`'s; the 0.16.4 entries for the two modules are no longer read. Every new or retried card is written by `claude-haiku-5-5` instead of `deepseek-v4.1-flash` ([D36](../decisions/d36.md)), in about 8 s instead of 40–60 s; cards written before keep the model they were written with. If the server's `.env` sets `OPENCODE_MODEL=deepseek-v4.1-flash`, remove that line or set `claude-haiku-5-5`, or it keeps overriding the new default. The gate's judge is Haiku as well; its calibration passed for every module but German, English and Chemistry, whose gate reports the judge as not calibrated until a later calibration passes.
