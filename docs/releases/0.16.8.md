# Vocabularium 0.16.8

## Upgrade

Upgrading from 0.16.7 to 0.16.8 keeps every account, deck, page, card and clip. Stop the API, back up with `npm run db:backup -- .data/backup-before-0.16.8.dump` (a file it has not written before), run `npm run db:migrate` (migration `0020` adds an empty `reports` table, [D336](../decisions/d336-report-a-problem.md)), start the API with 0.16.8, then replace the extension's files and reload it. A 0.16.7 extension works with a 0.16.8 API, without the new menu item; a 0.16.8 extension needs the migration, or saving a report fails.

What a user sees change:

- **Report a problem…** in the account menu, under Diagnostic logs ([decks and configuration](../screens/account-menu.md#report-a-problem)). From any screen it asks what the report is about (on a page, the whole page or one of its cards) and what went wrong, keeps the page as it is, the builds and, unless unticked, the diagnostic logs of the last 15 minutes, and says **Report saved**, with **Undo**.

What changes for the API and the owner's tools:

- `POST /api/reports` and `POST /api/reports/delete` (`docs/api/openapi.json`).
- `npm run reports -- pending | show <id> | issue <id> | filed <id> <issue>` reads the reports on this computer. It reads `.env` and `.env.postgres`, as `npm start` does. A daily Claude Code task on the owner's Mac files each new report as a GitHub issue with only its text, the screen, the module type and the builds, and opens fix PRs; the page and the logs never leave the computer ([diagnostic logging](../subsystems/observability-and-reports.md#reports)).
- For development: `npm run drive` runs the real extension and API on a disposable account for an agent to drive, `npm run check:sessions` checks every order of session, capture, publish and delete operations, and `npm run check` now also fails on unused files, exports, dependencies, locals and parameters.
