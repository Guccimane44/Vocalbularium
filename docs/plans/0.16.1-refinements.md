# Plan: refinements (0.16.1)

Draft for the owner's approval, 4 November 2026. Requested by the owner the same day; answers to the intake questions are recorded below each item.

## Outcome

Five refinements to the current product, released as 0.16.1. Items 1, 2 and 4 are polish; item 3 is a small redesign shown on a canvas first; item 5 lifts the rule that a card's facets follow the catalog order and needs a decision of its own (D26).

## Items

### 1. No inspirational copy

- **Before:** the dashboard reads "Keep the words and expressions you want to come back to." under "Your decks"; sign-in has the eyebrow "A home for the language you discover".
- **After:** both are gone in all six interface languages. Sign-in keeps "Welcome back." and "Sign in to open your decks and saved vocabulary." (owner, 4 Nov).
- **Where:** `extension/dashboard.tsx`, the sign-in view, `extension/locales/*/messages.json` (`dashboard.subtitle`, `login.eyebrow` removed).
- **Accept:** the strings no longer exist in any locale; the `dashboard` and `sign-in` screens show the title with no line beneath/above it, and nothing else moves except the space they took.

### 2. Expertise sample: word only

- **Before:** an Expertise module's page (Mathematics, Computer Science, Writing) shows a Word / Sentence switch above "See it on a card"; its facet pages show word and sentence tabs too.
- **After:** no switch on Expertise pages; the card shows the word sample. Languages pages keep their switch.
- **Where:** `extension/about-sheet.tsx` (`ModulePage`, the facet page's sample tabs), keyed on the Expertise family, not on module names.
- **Accept:** `module-page` for each Expertise module has no input-type control; Languages pages unchanged; `tests/extension.test.mjs` covers both.

### 3. Edit and Delete page, redesigned

- **Before:** two outlined buttons, "Edit" and "Delete page", beside the page title.
- **After (direction chosen 4 Nov):** a quiet pencil icon beside the title edits the main key; a ⋯ menu at the title's end holds "Delete page" in the danger colour, opening the existing confirmation. Both keep accessible names and keyboard use; Arabic mirrors.
- **Gate:** a canvas (light and dark, English and Arabic, rest, hover, menu open, editing) is published for the owner's verdict **before** product code.
- **Where:** `extension/page-view.tsx` (title actions), `page-view.css`, existing menu pattern from the deck menu, locale strings.
- **Accept:** the approved canvas matches the `page-*` screens; journey tests for editing the main key and deleting a page pass through the new controls.

### 4. One-per-page wording

- **Before:** "There is already a {name}."
- **After:** "Only one {name} module per page." (owner's wording, 4 Nov), e.g. "Only one Pronunciation module per page."
- **Where:** `shaping.blocked.single` and `api.moduleSingle` in all six locales.
- **Accept:** `tests/localisation.test.mjs` passes; the shaping notice and the API error show the new text.

### 5. Reorder facets within a card (D26)

- **Before:** a card's facets always follow its module's catalog order (enforced in `packages/domain/src/parents.ts`), and its tags follow that order.
- **After:** on a card, a facet's heading can be dragged up and down among the card's facets; the order is saved for that card only, and the edge tags, folded tags and rendered sections follow it. New cards and deck settings keep the catalog order. A facet added from the facet window goes to the end.
- **Decision D26:** a component's facet list is in the user's order, not the catalog's. Generation, prompts and checks are unaffected (they take the set, not the order); the samples and module pages keep catalog order.
- **Storage:** `components.facets` is already an ordered array, so no migration is expected; the contract's "in the parent's order" note and the order check change. A new store mutation (`reorderFacets`, idempotent by operation ID like every mutation) and its route; OpenAPI regenerated. Older builds' cards keep their catalog order, which is a valid user order: no upgrade step.
- **Interaction:** the same drag library and motion as module reordering (`shaping.tsx`): a grip on the facet heading, vertical-only, keyboard reorder (space, arrows), reduced motion respected, the order shown at once and restored on a failed save. Disabled while a card is editing or generating.
- **Where:** `packages/domain` (`parents.ts`, `content.ts`, `modules.ts`, `render.ts`), `packages/contracts/src/pages.ts`, `src/core/store-pages.mjs`, `src/server/routes.mjs`, `extension/card-content.tsx`, `facet-tags.tsx`, `page-view.tsx`; docs: product model, scope, generation architecture, traceability map.
- **Accept:** drag and keyboard reorder persist across reload; tags match section order in every layout; a replayed operation ID returns its first result; generation and Retry on a reordered card keep the order; `tests/server.test.mjs`, `tests/postgres.test.mjs`, `tests/extension.test.mjs` and a browser journey cover it.
