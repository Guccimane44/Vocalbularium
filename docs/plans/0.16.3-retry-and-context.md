# Plan: Retry and the context meaning (0.16.3)

Draft for the owner's approval, 5 November 2026. Requested by the owner the same day, in a Claude Code chat about how a card's Retry keeps its reading ([D19](../architecture/decisions/d19.md)). The owner proposed items 1–3 and agreed to the defaults below in the same chat.

Approved by the owner on 5 November 2026 ("Approve, start"). Decisions: [D28](../architecture/decisions/d28.md), [D29](../architecture/decisions/d29.md).

## Outcome

A card's Retry starts over, and a new Retry on the core rewrites the meanings while keeping the reading. Each reason to retry gets its own button:

| Action | Intent | Sends the saved core |
| --- | --- | --- |
| The card's Retry (and the page's) | "This card is wrong: read it again." | No: fresh, as on the first attempt |
| The core's Retry (new) | "The sense is right: write the meanings again." | Yes, and keeps the reading, flags included |
| A facet's Retry (unchanged) | "Write this part again." | Yes, as today |

Separately, a Languages card always gives the key's original meaning, and when the Context selects a sense, it puts that sense first under a label the module writes.

Two decisions: **D28** (items 1 and 2) amends D19 and D22; **D29** (item 3) changes the Languages cores' shape. Item 2 adds a button, so its placement goes on a **canvas** before any of its code is written.

## Items

### 1. The card's Retry starts over (D28)

- **Before:** a Retry of a content card, alone or with the page, sends the card's saved core as `previous` with `reading.prompt.md`, and the model keeps the card's reading unless the Context clearly contradicts it (D19). It reads afresh only after the main key changed (D22). The way to change a wrong reading is to edit the meanings and then retry (K58).
- **After:** a card's Retry, alone or with the page, sends the same request as the first generation: the main key, the Context and the instance ID. Nothing from the card goes with it. This holds for every content module, Languages and Expertise alike.
- **Goes:** `previous` on the card's and the page's Retry (`previousOf` in `store-generation.mjs`, its use in `generation.mjs`), and D22's check of a core written for another main key, which only existed to switch `previous` off.
- **Resolves again:** C28 (D17's "nothing from an earlier attempt is reused"), which holds once more for a card's Retry.
- **Where:** `src/core/store-generation.mjs`, `src/server/generation.mjs`, `packages/domain/src/composer/compose.ts`, the [Retry](../specs/capture-and-generation.md#retry) and [keeping the reading](../specs/capture-and-generation.md#keeping-the-reading) sections, [generation](../architecture/generation.md), [scope](../product/scope.md).
- **Accept:**
  - A unit test shows a card's Retry and a page's Retry compose the same request as a first attempt (no `previous` in the input, no `reading.prompt.md` in the instructions).
  - The browser E2E test that today checks a Retry sends the saved core is turned around: a card's Retry, after an edit to its meanings, sends no core.

### 2. A Retry for the core (D28, canvas)

- **Before:** the core has its own Edit (0.16.2) but no Retry. Its meanings are rewritten only by the card's Retry, which rewrites every facet too.
- **After:** a Retry beside the core's Edit, with the same icon, confirmation and behaviour as a facet's Retry. It writes the core again and keeps the card's reading:
  - **Languages:** the same `kind`, `language`, German's `gramRole`, and the sense the meanings describe (with D29, the context meaning too).
  - **Expertise:** the same `relevance` and the concept the explanation describes.
  - **Flags are kept as given.** The core Retry never changes a flag, so the facets that follow `gramRole` (Article, Conjugation, Declension, Comparison, Case) never fall out of step with it. To change the reading, the user uses the card's Retry.
  - **Facets stay untouched.** The core Retry writes the core alone. The top line is written by generation, as before.
- **Not offered** on a card without a core (never generated, failed or empty), on a card whose core was written for another main key, or on a spoken core (Pronunciation).
- **Contract:** a new generation target, `{ scope: 'core', componentId }`, beside `facet`. Regenerate OpenAPI. No stored data or migration changes.
- **Prompt:** the core Retry composes the module's `core.prompt.md`, then `reading.prompt.md`, with the saved core as `previous`, `facets` empty, and a schema holding the core alone. `reading.prompt.md` changes in every content module: it no longer says "follow the meanings over the other fields". It says to keep `kind`, `language`, `gramRole` (or `relevance`) as given and rewrite only the meanings (or the explanation). Its file name stays.
- **Gate:** a canvas showing the core's top line with Edit and Retry, at rest, hovered, asking to confirm, and regenerating, in light, dark and Arabic.
- **Where:** `extension/card-content.tsx`, `page-view.tsx`, `packages/contracts/src/pages.ts`, `src/core/store-generation.mjs`, `src/server/generation.mjs`, `packages/domain/src/composer/compose.ts`, every content module's `facets/core/reading.prompt.md`, locale strings in six languages, the [retrying one facet](../specs/capture-and-generation.md#retrying-one-facet) section.
- **Accept:**
  - A unit test of the composed request: core prompt plus reading prompt, `previous` holding the saved core, schema of the core alone.
  - A store test: the core Retry replaces the core and leaves every facet's text and the flags as they were. A replayed operation ID returns its first result.
  - A browser journey retries the core: the meanings change, the facets don't, and a facet edited meanwhile from a second installation stays.
  - The button is hidden in each of the "not offered" cases.

### 3. The context meaning first, the original meaning always (D29)

- **Before:** when the Context selects a sense, a Languages core can give only that sense. The *breadcrumb* card in the fourth deck (Context "breadcrumb ui") gives only "Navigationspfad in einer Benutzeroberfläche, der die Position innerhalb einer Website anzeigt". The word's own meaning, a crumb of bread, is gone.
- **After:** a Languages core gains an optional `contextual`, the meaning in this Context. `meanings` keeps the key's own senses and always includes its original meaning. The formatter shows the context meaning first, under a label the module writes. The model never writes the label:

  > 1. (in diesem Zusammenhang) Navigationspfad in einer Benutzeroberfläche, der die Position innerhalb einer Website anzeigt
  > 2. Brotkrümel; kleines Stück Brot

- **Rules:**
  - **Words and phrases only.** A sentence's translation already follows its Context, so it gets no label.
  - **No Context, or a Context that does not narrow the sense:** no `contextual`, and the core reads as today.
  - **No duplicate.** When the Context selects the ordinary sense (*Bank* in a finance article), that sense is the labelled line and is not repeated below it.
  - **The grammar word follows the first line**, the context meaning (*die Brotkrümelnavigation*).
  - **Pronunciation never speaks the label.**
  - **The label belongs to the module**, like its header labels: German `(in diesem Zusammenhang)`, Chinese `（在此语境中）`.
- **Reading it back:** the core's `read` turns a stored first line that starts with the label back into `contextual`, so the facet Retry, the core Retry (item 2), the core's Edit and the providers' `providerCore` keep it. A user who deletes the label while editing turns that line into an ordinary meaning.
- **Stored form:** still markdown, one meaning per line. Existing cards keep their form until retried. No migration.
- **Out of scope:** the Expertise modules, whose explanation works differently.
- **Where:** in `packages/domain/src/catalog/languages/{german,chinese}/`, the core's `facet.ts` (shape, `format`, `read`, `checks`), `core.prompt.md` and `rubric.md`, plus their golden sets. Also the Pronunciation facets' spoken lines, `domain/content.ts` if the formatter needs a helper, and the [modules](../specs/modules.md) spec's core section.
- **Accept:**
  - Unit tests of `format` and `read`: they round-trip with and without `contextual`, and an edit that deletes the label becomes an ordinary meaning.
  - A content check: the label appears at most once, and only on the first line.
  - Golden sets gain cases with Context in both modules (*breadcrumb* / "ui", *Bank* / a finance sentence, *Schloss* / a door, *行* / a bank), and one without Context. `npm run gate -- german` and `npm run gate -- chinese` pass, with the rubric scoring "original meaning present, context meaning first and labelled".
  - Pronunciation's audio lines carry no label.
  - A browser smoke check regenerates the *breadcrumb* card and shows both lines.

## Increments

1. **Decisions.** `d28.md` and `d29.md`, two traceability-map rows, and C28 marked resolved again, with Notion records once the owner approves.
2. **Item 3 (D29).** Catalog-only, so it can start right away. It changes `core.prompt.md` and the prompt fixtures.
3. **Item 1 (D28).** The fresh Retry. It changes the composer and the prompt fixtures, so it lands after item 3 to keep the fixture regeneration in one place at a time.
4. **Canvas** for item 2, while items 2 and 3 are under way.
5. **Item 2 (D28).** The core Retry, after the canvas is accepted and item 1 has landed.
6. **Release 0.16.3:** the upgrade note in [scope](../product/scope.md#upgrade-from-earlier-builds) ("no stored data changes; existing cards show the context meaning only after a Retry"), and the review packet.

Each increment merges when its CI is green. Prompt changes show in `tests/prompts/*.txt` (`UPDATE_PROMPTS=1`).

## Not in this plan

- An option listing a key's other readings to pick from.
- Editable flags.
- A context meaning for the Expertise modules.
