# 0.7.1 Facet tags: verification and candidate

15 October 2026. Release 0.7.1 is the owner's change list given in a Claude Code chat on 15 October 2026, delivered in [PR #147](https://github.com/Guccimane44/Vocalbularium/pull/147) and tracked in the 0.7.1 milestone in Actual Stages. It covers:
- facet tags marked with their abbreviations, in the parent's order;
- four motions: fly in, along the edge when the card folds, back when it unfolds, pop on delete;
- every deck settings module drawn as an empty card;
- no reason text for an unavailable facet in the module window.

The [pages specification](../../specs/pages-and-editing.md#facet-tags) describes the behavior.

The first 0.7.1 build, from `0a332f7` (SHA-256 `734955b01f38dd0c37d1038c2fa97f2136a56a2291e6d996554c53563b017bdb`), is superseded and was never handed over. On a folded card its tags hung a full tag's height below the card's bottom edge, over whatever came next; `4be5c9f` fixes this, and the browser test now checks that the tags start on the edge. It is kept locally as `vocabularium-0.7.1-local-candidate-0a332f7.zip`.

The second build, from `4be5c9f` (SHA-256 `64aff97d547ef1af03a11ca549ff8e9d5587aea4ec8eb27ba64cfe99516fc4fa`), was handed to the owner on 15 October 2026 and is superseded too. It is kept locally as `vocabularium-0.7.1-local-candidate-4be5c9f.zip`. The owner found folding and unfolding with tags not smooth, and asked what happens to a parent's tags with ten facets. `b1036d6` makes these changes:
- **Folding and the tags take turns.** The tags first travel along the still edge on a rounded, evenly paced path. The card then folds over 500ms, up from 450ms, with the tags riding its bottom edge. Unfolding runs the other way.
- **The card no longer jumps.** A row transition in `motion.css` had replaced the card's own transitions, so its padding jumped on every fold.
- **Ten facets fit.** Tags below a tab hang from a rail that reaches past the tab when there are more tags than it is wide. A card with content is at least as tall as the tags on its left edge.

A scratch build with ten German facets, not committed, checked every layout. Sampling one tag frame by frame showed that the card's height no longer jumps and the tag changes direction only once, where the card begins to fold.

The upgrade from 0.7.0 has no migration and keeps every deck and page ([scope](../../product/scope.md#upgrade-from-earlier-builds)). The owner accepted 0.7.1 in a Claude Code chat on 15 October 2026, and the 0.7.1 milestone in Actual Stages is Done. At that time the local API on `127.0.0.1:4318` was still a process started before 0.7.1, so it reported version 0.7.0; the only server change in 0.7.1 is the version string.

## Automated verification

Run in a Linux cloud container on source revision `b1036d6`:
- PostgreSQL 18.4 with disposable databases.
- Playwright driving the pre-installed Chromium build 1194, not the build Playwright pins.
- Controlled generation providers: no live model calls, and not the owner's account.

Results:
- `npm run check`: passed.
- `npm test`: 153/153. This includes the new abbreviation test in `parents.test.mjs`: every facet type has one, no two types share one, and one facet type has the same abbreviation on every parent.
- Browser: 27/27 (`app.browser.test.mjs`, `logging.browser.test.mjs`) against the **extracted candidate** (`VOCABULARIUM_TEST_EXTENSION`); scenarios that build their own testing extension use that build instead. Port 4318 was free in this environment. The new scenario *facet tags* checks the following:
  - **Marks and placement:** marks Ar, Ex, Sy, An in order; geometry on the left edge, on a folded card's bottom edge, and hung below the tab in deck settings, where the rail reaches the last chain.
  - **Fold and unfold:** every keyframe keeps to the left column or the bottom row within the rounded turn; the card waits for its tags before folding, and its fold transitions are not replaced; unfolding, the tags wait on the bottom edge and set out from the opened card's bottom.
  - **Clicking a tag:** on a folded card it unfolds the card and focuses the facet's section.
  - **Deleting:** a facet with content asks first and its tag pops; a facet waiting for Retry goes at once.
  - **Adding:** a facet added with **+**, or dragged in deck settings, flies its tag in; the last tag pops, and a facet added afterwards still flies in.
  - **Reduced motion:** no tag animation starts.
- The existing *parents and facets* and deck settings scenarios cover deck settings modules as empty cards: Remove behind the tab, the outlined main key, and keyboard reordering by the tab.
- CI on PR #147.
