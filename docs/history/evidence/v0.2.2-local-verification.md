# v0.2.2 save-feedback verification

20 September 2026. [Tracker #40](https://github.com/Guccimane44/Vocalbularium/issues/40) records the review PR, configured candidate source/checksum, CI and hosted outcome. The baseline is `08b739619f2407d53fc36b05071786372f91ab13` from the still-open v0.2.1 PR #39.

## Corrected behavior

The owner identified the brief extra row as the amber save-recovery panel reproduced during successful publication. Previously, every durable `save-*` record displayed that panel, even while the corresponding request was progressing normally.

Save operations now persist an explicit active state before submitting, remove the receipt on success, and expose pending recovery on failure. A fresh worker converts retained active records to pending recovery once before accepting operations. Concurrent submissions for the same operation share the active request. Legacy records without a state still show recovery. Existing validation-error dismissal and stale generation-session reconciliation remain effective.

This applies to automatic page publication and account mutations. Durable operation IDs and payloads are preserved, so retry can recover a lost acknowledgment without repeating its effect or regenerating content. The authoritative behavior is in [Select and Add](../MVP-Product-spec-select-and-add.md#saving-and-synchronization-failures).

## Verification

Environment: macOS, Node 24.19.0, Playwright 1.62.1 and Chrome for Testing 151.0.7922.34. Local tests use isolated profiles, synthetic data and local servers; they do not use the hosted account or live generation provider.

- New logic coverage verifies active/failure/success transitions, concurrent request reuse, exact retry payload preservation, interrupted-save recovery without automatic resubmission, compatibility with legacy receipts, and existing validation-error dismissal.
- The browser regression holds real publication requests while Recent captures and the deck list are both open. In Light and Dark, DOM observers record zero recovery-panel insertions throughout successful captures, including brief flashes. Captures finish normally.
- Deliberately failed publication shows recovery in both views. Explicit retry hides only the operation currently being submitted and completes the same cards; other failed operations remain actionable.
- A separate browser scenario holds the response to a committed default-deck save, closes its dashboard and actually stops the extension worker. The new worker exposes the exact original receipt. Retrying acknowledges that operation and preserves a newer intervening default-deck change, demonstrating safe replay.
- `npm ci`, `npm run check`, all **49** logic tests (`npm test`) and all **16** browser scenarios (`npm run test:browser`) passed. Current-head CI is recorded in #40. Existing coverage includes pending-row continuity, lost acknowledgments, capture feedback, multiple installations, worker suspension, abrupt browser exit and generation-session cancellation.
