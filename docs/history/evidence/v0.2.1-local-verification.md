19 September 2026. The owner authorized the [execution plan](../MVP-Execution-plan-v0.2.1.md). The baseline remains the unmerged v0.2.0 candidate `ae94bd7e594a8e8fc75dd482b2b6fe855647ed54`. Exact configured-package source/checksum, current-head CI and the extracted-ZIP hosted result are recorded in [tracker #35](https://github.com/Guccimane44/Vocalbularium/issues/35).

## Implementation

- `3b883b6`: remove the Recent captures empty-state instruction and pending saving paragraph/tooltip. Pending receipts keep their clock/tint and accessible **Pending** state. Failed-save explanation, error and resubmission remain.
- `12ee3e7`: extract the existing webpage popup renderer unchanged into a shared module and route dashboard feedback internally. The receiver checks the worker's extension ID/URL and originating tab ID. Its shadow host sits outside the replaced account content. Theme updates do not rebuild feedback or restart timers.
- The capture-time page URL prevents closed/navigated dashboard captures from falling into the separate-window path. If Chrome omits a tab URL, [runtime.getContexts](https://developer.chrome.com/docs/extensions/reference/api/runtime#method-getContexts) identifies the extension's own tab without additional permissions. External-page injection, its existing CSS, and the restricted-page fallback remain unchanged.

## Controlled checks

Environment: macOS, Node 24.19.0, Playwright 1.62.1, Chrome for Testing 151.0.7922.34. Browser fixtures use isolated profiles, local servers and synthetic data.

- `npm ci` and `npm run check`: dependency installation and syntax/JSON/whitespace checks passed.
- `npm test`: all 46 logic tests passed.
- `npm run test:browser`: all 14 scenarios passed. Coverage includes capture/save recovery, continuous pending-row handoff, multi-installation editing, page retry, actual worker suspension/restart, browser reopening and abrupt process termination.
- The new dashboard regression counts both calls to `chrome.windows.create` and `windows.onCreated` events throughout the test: both remain zero, including for closed and navigated origins. Nine invocations save nine independently completed cards.
- Only the originating dashboard receives feedback; another open dashboard stays clear. Focus and route remain unchanged. A message from another dashboard cannot forge the worker-only feedback route.
- Computed text, popup and close-button bounds, typography, spacing, colors, borders and shadows match external feedback exactly in both themes. Screenshots below were inspected. The external renderer body and theme/feedback CSS retain the accepted baseline presentation.
- Account rerenders preserve the original feedback DOM. The test waits 1.2 seconds before switching theme and asserts removal on the original approximately three-second deadline, so restarting the timer would fail. Rapid captures retain independent items and manual dismissal removes only its target.
- Empty Recent captures has no following helper element in either theme. Pending fixtures retain exactly one paragraph (the captured text), a **Pending** tooltip/accessibility label, and the clock/tint. Failure recovery and the controlled delayed account handoff remain covered.

During development, the sandbox blocked local server binding; the authorized browser runs used local-server access. An obsolete temporary Chromium directory was also replaced with the installed Playwright browser path. The first route test exposed omitted tab URL metadata; the own-context lookup fixes that without adding permissions. A visual comparison initially saw a hovered close button on only one surface; moving both pointers away made the comparison equivalent. These are resolved; no failing check is counted as passed.

Its actual result and the archive verification belong to #35 alongside the candidate's exact source and SHA-256. The delivered 0.2.0 archive and checksum are preserved.
