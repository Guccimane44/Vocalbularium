# Stage 6 bounded reads — local verification

26 September 2026. The v0.3.0 bounded-read branch follows the Stage 6 generation branch. It adds bounded deck summaries, card pages, individual card/deck reads, recent captures and a backfilled front-text sort key. The extension retains an offline default-deck snapshot, fetches details on demand, and removes saved local capture receipts only after confirming the server card and rechecking the receipt state. Pending and interrupted saves remain local for explicit recovery.

Controlled checks on macOS with Node 24, PostgreSQL 18 and Chromium 151.0.7922.34:

- `npm run check`: passed syntax, JSON, whitespace and TypeScript checks.
- `npm test`: 79 passed. The bounded-read fixtures include 64 cards across all four sort orders, 56 decks across two pages, 25 captures with a 20-row recent limit, authenticated read routes, page-size rejection, stale-cursor rejection, and receipt cleanup during a concurrent state change.
- `npm run test:browser`: 18 passed. Scenarios include the pending-to-card handoff with no empty or duplicate frame, deck replacement beyond the first page, card sorting, offline draft recovery, two installations, worker restart and browser restart.
- `npm run openapi`: regenerated the API description for the new read routes.

The synthetic fixtures establish correctness and bounded response shape at those sizes. They do not establish a user-count capacity target. The older `/api/account` route remains for compatibility; the current extension uses bounded routes. No hosted provider or deployment was involved.
