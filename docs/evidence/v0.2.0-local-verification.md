# v0.2.0 local verification

13 September 2026. The source changes are reviewed in [PR #34](https://github.com/Guccimane44/Vocalbularium/pull/34), with the final package revision and CI links recorded in [delivery issue #33](https://github.com/Guccimane44/Vocalbularium/issues/33). These are controlled local checks on macOS using Node 24 and Chrome for Testing 151.0.7922.34, not owner Windows acceptance.

- All 46 backend, provider, store, ordering, and extension-menu/synchronization checks passed.
- All 12 browser scenarios passed, including real worker suspension/restart and abrupt browser exit. New coverage exercises shared deck actions, failed-save recovery, deletion/default replacement, keyboard menu dismissal, appearance persistence, active feedback, and card rows.
- Syntax/JSON/whitespace checks and the local extension build passed. The test scripts were run with the required Node 24 runtime.
- Theme changes preserve manual text, selection, configuration drafts, the selected configuration page, and open dialogs. They reach other extension views, injected capture feedback and the restricted-page fallback popup. Logout and browser restart preserve the preference; another installation retains its independent preference. Injected scripts remain unable to read trusted local storage.
- Feedback closes on its original three-second timer; switching theme does not restart it. The existing capture test also checks manual dismissal and independent receipts.
- Entire card rows open the correct card through the index, text, status icon, whitespace and keyboard. Text selection does not navigate. All four sort orders, calculated indices, empty entries and neutral manual cards pass. Card detail retains generation status. Unsaved captures retain error text and explicit resubmission.
- Controlled late and overlapping account responses cannot restore capture after logout or overwrite a newer synchronized menu name. The menu updates without replacing the generation session. Unicode, quotes, long names and literal `%s` are covered. Chromium substitutes every literal `%s` and does not implement a percent escape, so the displayed title inserts an invisible separator between `%` and `s`; the stored deck name is untouched. Native Windows presentation remains an owner check. [Chromium title implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/extensions/menu_manager.cc)

## Contrast and visual review

The browser scenario measures the actual theme tokens against surface, page, hover and all three state backgrounds. Normal/muted text, primary-button text, status icons, focus rings and control borders are included. Decorative separators and disabled controls are not treated as required control cues.

| Theme | Lowest normal-text contrast | Lowest required cue/focus/border contrast |
| --- | --- | --- |
| Light | 5.39:1 | 3.15:1 |
| Dark | 5.96:1 | 3.18:1 |

Both exceed the agreed 4.5:1 text and 3:1 cue thresholds. The check/clock/warning shapes and accessible descriptions remain distinct when colors cannot be distinguished. Screenshots were inspected for normal themes, a 390-pixel window with long unbroken content, forced colors, red/green color-vision simulation and grayscale. Chromium also produced protanopia and tritanopia views for both themes. Simulations supplement the non-color cues; they are not a medical or broad accessibility certification.
