## Decision

A parent's content becomes **structured data** instead of markup text, so each facet fills its own container and the editor shows fields instead of syntax. Generation asks the provider for a JSON object per parent: a **core** (a word: the key's language, the key, an optional romanization and a list of meanings; a sentence: its translation) and one entry per facet it was asked for, each in its own shape: Article `{ singular, plural }` with the plural optional, Examples a list of `{ sentence, translation }` numbered by position and not tied to meanings, Synonyms and Antonyms lists of words, Pinyin a list of `{ text, pinyin }` (one per meaning for a word, one for a sentence). A facet that does not apply, or that the provider leaves out or empty, has no content. The result is validated against the parent's shape; anything else fails the attempt. The component stores that object as a typed block in its block document ([Q13](../questionnaire/answers/answers-03-frontend.md#q13)), and the card is rendered from it into fixed containers: the core, then one container per facet in the parent's order, looking as in 0.7.3. **Editing** a parent card turns the whole card into fields in place, with one **Save** and **Cancel**: the meanings or the translation, then each facet's fields; list items (meanings, examples, synonyms, antonyms, Pinyin lines) can be added at the end and deleted, not moved, and numbering follows. The module's name, the facet names and the core's top line (language, key, romanization) are shown but never editable, and no structuring syntax is ever shown. A facet without content appears in the editor as an empty container the user can fill. Every field may be left empty, the core's included, and Save never refuses for it: a row with nothing in it is dropped, an item keeps the parts that have text and the card shows those parts, and a facet emptied completely has no content. Generated results stay complete. Facet **Retry** and **Delete** act on the facet's entry. The upgrade discards every deck and page, keeps sign-in and starts a fresh My Deck, as in 0.7.0. The card's look is otherwise unchanged; the interpretation model is unchanged. Supersedes the render-only parsing of [C17](../traceability-map.md#conflicts) (C21). *Amended 16 October 2026, before implementation:* the owner dropped the rule that the core keeps one meaning or its translation, and the rule that a part-filled item is refused. *Amended again 16 October 2026, after reviewing the field editor (#159, closed unmerged):* each facet, and the core's meanings or translation, is **one markdown text** instead of items. The provider still returns JSON in the shapes above, validated strictly; when a result is stored, the app formats it into markdown as the card looks: meanings as a numbered list, Article as one line `die Show · die Shows`, Examples as a numbered list with each translation on the next line in italics, Synonyms and Antonyms as one comma-separated line, Pinyin as a line each. The core's top line (kind, language, key, romanization) stays structured and locked. Supported markdown: bold, italic, bulleted and numbered lists, inline code and highlight (`==text==`). The card renders each facet's markdown inside its fixed container; nothing renders as HTML. Editing is **live formatting** (TipTap): one editor per facet and one for the core, with no fields, item numbers or separators of its own, and any facet may be emptied. Facet Retry formats its new JSON into that facet's markdown. The upgrade discards decks and pages again (migration 0013), keeping sign-in.
