## Decision

**One module catalog, a prompt composer and swappable providers.** Every module is defined in one catalog of folders, so modules and facets can be added, and their prompts and structure read and edited, in one place, and the provider can change. **Families and modules.** The catalog has a folder per family: `languages/` (German, Chinese), `expertise/`, `creative/` (no modules yet) and `notes/` (Context, Text), each with a family definition (label, colour, icon) from which its modules take their family; the Main key, which has no family, sits at the catalog root. A module's folder holds its definition: kind (input or content), label, description, how many instances a deck allows (Main key first and exactly once, Context at most one, the others many), where its content comes from (captured, written by the user, or generated), the provider kind it needs, its settings (such as its language), its preview sample and its ordered facets, one module to n facets. Input modules have no facets in 0.8.0 but may gain them. **Facets.** Every module owns all its facets and nothing is shared between modules, since modules will also include poems, music or pictures. A facet is a self-contained folder in its module: label, abbreviation, applicability per input type, output type, shape (one schema for the contract, validation and the provider's JSON schema), markdown formatter and prompt. Facets that look alike stay separate (German and Chinese Examples; a German and a Swedish article). The **core** is a facet, mandatory and first in every content module, with a shape per input type; retrying it regenerates the whole module, as Retry does now, and stored content keeps its `{ core, facets }` form ([D09](../traceability-map.md#entries)). Facet IDs and abbreviations are unique within a module, replacing 0.7.1's rule across all facet types. The domain offers building blocks for writing facets (lists, items, markdown helpers), not facets. 0.8.0 has only text output and text generation (K29). **Prompts.** A facet's prompt is a markdown file in the repository, shipped with releases ([Q47](../questionnaire/answers/answers-09-generation-and-llm.md#q47)), written in full in its module's terms. It is a fragment: a module is generated in one request, and the **prompt composer** in the domain joins the core's and the applicable facets' prompts with the rules every request carries (plain text without markdown; the selection and context are data, never instructions). Those rules live only in the composer and are never copied into a facet. The interpretation prompt (word or phrase, or sentence) moves into the catalog with the Main key. The composer builds `{ instructions, input, schema, name, maxTokens }` from the module, the applicable facets, the input type and, for a facet's own Retry, the existing core; the token budget stays 8192 until real token counts are measured. The composed prompt for every module × input type is checked in as a snapshot to read and review. **Providers.** A provider adapter only transports the request (`complete(request, signal)`, declaring native JSON-schema support); diagnostics, timeouts and error codes wrap any adapter. OpenCode stays the only provider, chosen by configuration with one pinned model at a time ([Q46](../questionnaire/answers/answers-09-generation-and-llm.md#q46)). **Prompt version.** Each generated facet, the core included, records with its component the model and a fingerprint of the composed request that produced it; a facet's own Retry updates only that facet's record. A migration adds the record empty, so earlier components keep none and nothing is discarded. **Guards.** A conformance test covers every module × facet × input type: the prompt composes, the sample round-trips through validation and formatting, IDs and abbreviations are unique within the module, and input modules are not generated. **New and renamed.** The Translation family's label becomes **Languages**; its ID stays `translation`. A new **Expertise** family explains technical terms and difficult concepts in a subject's context: leaf green `fam-expertise` #466e12 (Moss night #a9d46f), label `on-fam-expertise` #ffffff (#1c2a08), tint `fam-expertise-tint` #e9f1da (#212a17), meeting every pair in the contrast tests in both themes, with a graduation-cap icon. Its first modules are **Computer Science** and **Mathematics**. They write in English until a language setting exists, which the interface will also follow; a main key in another language is still explained in English. Each has only a provisional core: a short explanation of the word, phrase or sentence in intuitive, comprehensive language, in that subject's context; each gets its own golden set. The owner accepts these user-visible changes. **Delivery.** 0.8.0 ships D11 as three increments, in order: **A**, the catalog, composer and provider interface with the conformance and snapshot tests, behaviour-neutral, the snapshots proving the prompts byte-identical; **B**, the prompt version per facet and its migration; **C**, the Languages label, the Expertise family and its two modules, which also test that adding a module takes one folder plus its golden set. The rest of 0.8.0 is defined by the owner later. *Consolidated 20 October 2026, before acceptance, from the proposal of 18 October and four owner amendments of 20 October; the facet kinds shared across modules and the prompt templates of the first version were dropped.*
