# D19: A card's Retry keeps the card's reading

Full entry of the [traceability map](../traceability-map.md#entries).

- **Opened:** 2026-10-29
- **Source:** Owner question in chat, 29 October 2026: a card's Retry "seems quite easy to lose the context of the module"
- **Affected docs:** [capture and generation](../../specs/capture-and-generation.md#keeping-the-reading) (what a Retry reuses, keeping the reading), [generation](../generation.md) (the composer's `reading.prompt.md` and `previous` input), [modules](../../specs/modules.md) (a reading prompt per content module), [golden sets](../../../tests/golden/), [scope](../../product/scope.md)
- **Open items:** — (C28, K58–K61 resolved with their proposed defaults)
- **Notion:** [Accepted 2026-10-29](https://app.notion.com/p/407bb135020881ddbb7ff37a32846f93)
- **Status:** implemented (0.12.2); [reading check](../../history/evidence/reading-check.md)

## Decision

**A card's Retry keeps the card's reading.** Until then a Retry of a card, or of the page, sends only the main key and Context, the same request as the first generation, so the model decides the reading again and can change it (*Bank* as a bench, then as a bank). A Retry of a content card that has a core also sends that core, as saved, as `"previous"`, with the module's new `reading.prompt.md`: write the card again, keeping its reading unless the Context clearly contradicts it. The reading is, for the Languages modules, `kind`, `language`, German's `gramRole` and the sense the meanings describe; for the Expertise modules, `relevance` and the concept the explanation describes. Every text is written anew, the facets included; only the reading carries over. The core as the user last saved it counts, and its meanings outweigh its flags, so editing the meanings and then retrying is how a wrong reading is changed (K58). A card without a core (never generated, failed or empty) generates as today. A facet's own Retry is unchanged. No stored data, migration or interface change.
