## Decision

**A Retry after a changed main key reads the new key; facet tags without interaction; no deck-settings preview; folded modules in deck settings.** A card's Retry, alone or with the page, gives its core as `"previous"` only while the core was written for the page's current main key (its top line's key, trimmed, equals the main key); after the user changes the main key the card generates as on its first attempt, so the old key's reading no longer carries over (amends D19, which kept the old key's reading). A facet tag is no longer a button anywhere: on an open card's edge it no longer pulls out to a Retry (0.7.4), and no tag shows a remove on its corner (0.7.3); a facet's Retry and Delete beside its label and the facet window remain. Deck settings lose their **Preview** (D07's dialog, with D20's samples): the owner found it misleading after first asking for its header to be fixed; a module's page keeps its samples. An open six-dot menu or facet window stands over the facet tags hung below a tab, which before covered the menu. Every module in deck settings, the main key included, is drawn as a folded card that never unfolds, its facet tags hanging from the end of its bottom edge, in place of D06/0.7.1's tab alone with tags hung on chains (owner, 30 October 2026: "replace this deck layout UI with the folded module UI", then "never unfolds"). A module added after the page was scrolled no longer makes every entry replay from below: the entries' places are measured from the list, not the window (owner report, 30 October 2026). No stored data, migration or API change.
