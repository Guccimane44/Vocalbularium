# D28: a card's Retry starts over; the core's Retry keeps the reading

Full entry of the [traceability map](../traceability-map.md#entries).

- **Source:** the owner's question in a Claude Code chat, 5 November 2026: when a user retries the whole card, "does that also mean user might not like the previous read?" The owner then proposed "a real retry … no context from the previous read" for the card, and a Retry beside the core's Edit that keeps the reading. ## Context

Since D19 (0.12.2), a Retry of a content card, alone or with the page, sends the card's saved core as `previous`. The model keeps the card's reading unless the Context clearly contradicts it. A user who disliked the reading had to edit the meanings and then retry (K58), and nothing in the interface said so. K58 kept a **Start over** action as a later option. A user who presses the card's Retry may want either a new reading or new wording, and one button cannot tell which.

## Decision

Each reason to retry gets its own action:

| Action | Intent | Sends the saved core |
| --- | --- | --- |
| The card's Retry, and the page's | Read the key again. | No |
| The core's Retry (new) | Keep the reading, write the meanings again. | Yes, flags kept |
| A facet's Retry (unchanged) | Write this part again. | Yes, as before |

- **The card's Retry starts over.** A Retry of a content card, alone or with the page, sends the same request as the first generation: the instructions, the main key, the Context and the instance ID. Nothing from the card goes with it. This holds for every content module. D22's check of a core written for another main key goes with it, since it only decided when `previous` was sent.
- **The core gets a Retry** beside its Edit, with a facet Retry's icon, confirmation and behaviour. It writes the core alone, keeping the card's reading:
  - **Languages:** `kind`, `language` and German's `gramRole` are kept as given, as is the sense the meanings describe, including D29's context meaning.
  - **Expertise:** `relevance` and the concept the explanation describes are kept.
  - **The flags never change**, so the facets that follow them stay in step. A user who wants another reading uses the card's Retry.
  - **Every facet stays as it is.** The top line is still written by generation.
- **The core's Retry is not offered** on a card without a core (never generated, failed or empty), on a card whose core was written for another main key (its top line's key, trimmed, differs from the main key), or on a spoken core (Pronunciation).
- **Contract:** a generation target `{ scope: 'core', componentId }`, beside `facet`, idempotent by its operation ID like every mutation. OpenAPI is regenerated.
- **Prompt:** the core's Retry composes the module's `core.prompt.md`, then `reading.prompt.md`, with the saved core as `previous`, `facets` empty, and a schema of the core alone. `reading.prompt.md` now says to keep the flags as given and write the meanings (or the explanation) again. It no longer says the meanings outweigh the flags.

No stored data or migration changes. Existing cards are unaffected until retried.

## Alternatives considered

- Keep D19 and add a **Start over** beside the card's Retry (K58's later option). This keeps the less expected behaviour on the familiar button.
- Let the core's Retry change the flags when the meanings were edited, and regenerate the facets that follow them. This blurs the two actions and lets the core fall out of step with its facets.
- A hint explaining that Retry keeps the reading. Cheaper, but the user still has to edit the meanings by hand.

## Consequences

- A Retry is "start over" again, as before 0.12.2.
- An ambiguous key with little Context can change its reading between card Retries. That's the drift the [reading check](../../history/evidence/reading-check.md) measured and D19 removed. The Context still anchors the reading.
- A user's edit to the meanings no longer steers the card's Retry. It does steer the core's Retry, and every facet's own Retry.
- K58's "edit the meanings, then Retry" is no longer the way to change a reading.
