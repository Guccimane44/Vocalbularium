## Decision

**A writing guide per language for the Expertise family; English stays the only prompt.** The Expertise modules' output should read as written in the interface language, not translated into it. The guide belongs to the Expertise family: the Creative family, which writes something new from the key, will have different language requirements and is left untouched until its first parent ([modules](../../specs/modules.md#module-families)); any later family gets a guide only by its own decision. **Writing guide.** The Expertise family holds one short writing guide per interface language, written in English with examples in that language, so the instructions stay in the language models follow most reliably and can be checked once: the register (a good textbook, not a translation), stock phrases to avoid, how a technical term is written at first use (the established term with the English in brackets, which also makes an invented term visible; English kept where no translation is current), code and identifiers left untranslated, the language's punctuation, and how a length limit is counted (words, or characters for Chinese). The prompt composer adds the guide of the interface language to every Expertise request, beside the rules every request carries ([D11](../traceability-map.md#entries)), so no Expertise module repeats it and a new one gets it without work. **English prompts only.** Module prompts and the shared rules stay in English in every language; no module has a translated prompt. A translated instruction can lose a rule unnoticed in a language nobody on the project reads, and output in a less-trained language is no more reliable for it. Translated prompts can return only as a new decision, with evidence for a specific language. **Review per language.** Expertise generation in a language is checked before that language is offered: the Expertise golden sets run in it and are reviewed, as each language's interface strings are (K42). **Unchanged:** which content follows the language preference ([D14](../traceability-map.md#entries), K36), the Languages modules, which write in their own language, and the Creative family, neither of which gets a guide (K39); the shared rules stay in the composer; the prompt version still fingerprints the composed request, so a guide changes it for that language only. **Evidence:** in round two (306 calls), the English prompt with a length rule in the language's unit and a guide came close to the fully translated prompt in Chinese and French, and both were well ahead of the current prompt in Chinese; in French the current prompt was already fluent. The guide tested there was written in the target language; a guide written in English is untested (K43). *Revised 23 October 2026, before acceptance: the first draft also allowed a module to add translated prompts on evidence; the owner dropped them as unstable in less-trained languages such as Dutch. It also gave every family that writes in the interface language a guide; the owner narrowed it to the Expertise family.*
